## 2. 평가방법 유형별 샘플 템플릿 설계

기존 `exam/dbms/sample1.html`(빈칸 243개)은 C형 전용이다. 나머지는 형태가 달라야 한다.

### A형 — 포트폴리오 (산출물 제출형) · 01,02,03,11,12,17

평가 대상 = 학생이 만들어 낸 결과물. 빈칸을 채우는 시험이 아니라 작품집을 완성하는 것.

```
머리말      능력단위·수준·평가방법·배점·평가일·제출기한
제출물 명세  무엇을 몇 개 만들어 어떤 형식으로 내는가 (체크박스 목록)
과제 1..N   각 과제 = 채점표 1블록
  ├ 과제 지시문 (hwp 작업지시서 원문)
  ├ 대응 수행준거 뱃지 + 배점 + 난이도
  ├ 작성 양식      ← LM 활용 서식을 표 입력 위젯으로
  ├ 산출물 업로드   ← 이미지 드롭존
  ├ [예시 보기]     ← 완성 예시 펼침 (기본 접힘)
  └ 자가 점검       ← 채점표 항목을 학생이 미리 체크
제출 요약    체크 집계 + 미완성 경고 + 제출물 목록 복사
```

핵심 위젯 : 표 입력 · 이미지 드롭존 · 자가점검 체크 · **예시 채움 토글**. 빈칸은 거의 쓰지 않는다.

**예시 제공 방식은 C형(`exam/dbms/sample1.html`)의 「정답 보기」와 같게 한다.**
접힌 예시 블록을 따로 두지 않고, 모든 입력칸에 `data-a`(예시 답안), 드롭존에 `data-aimg`(예시 그림)를 달아
[예시 보기] 를 누르면 **칸이 실제로 채워지고 그림이 들어간다.** 학생이 쓰던 답은 배열로 보관했다가
[예시 숨기기] 에서 되돌리고, 예시를 보는 동안에는 localStorage 저장을 막는다.
`.ex` 블록은 표를 중복해 보여 주는 자리가 아니라 **왜 그렇게 썼는지에 대한 해설**만 담는다.

예시 그림은 PNG 캡처 대신 **직접 작도한 SVG 파일**(`img/sample1/*.svg`)로 둔다.
브라우저가 실제로 그리므로 합성이 아니고, 인쇄·확대에도 깨지지 않으며 7장 합쳐 19KB 다.

### B형 — 평가자 체크리스트 (수행 관찰형) · 04,07,10,13,15

평가 주체가 강사다. 학생용과 강사용 두 벌이 필요하다.

```
[학생용 수행지시서]  수행 절차 STEP 1..N + 단계별 증빙 캡처 + 완료 선언
[강사용 채점판]      항목별 체크 → 자동 합산 → 총점/성취수준/합격여부
                    미달 항목 목록 → 피드백 문구 생성 → 결과 복사
```

### C형 — 문제해결 시나리오 (과제 수행형) · 08,14,16

평가 대상 = 문제를 푸는 사고 과정. 답만이 아니라 근거를 쓰게 한다.

```
시나리오 지문 → 문제 1..N (실행 지시 · 결과 입력 · 실행결과 캡처 · 판단 근거 서술)
```

기존 `exam/dbms/sample1.html` 이 이 유형의 완성 구현체다. 이 파일을 C형 기준으로 삼는다.

### D형 — 혼합 (서술형 20 + A/B/C 80) · 05,06,09

```
PART 1  서술형 (20점)  짧은 답안칸 + 채점 포인트 토글
PART 2  해당 유형 그대로 (80점)
총점 = PART1 + PART2, 배점 합계 100 자동 검증
```


경로는 `exam/mNN/` 으로 통일. 기존 `exam/dbms/` 는 16번 전용으로 유지.

## 4. 품질 기준

1. hwp 평가도구의 작업지시서·채점표 문구를 임의로 바꾸지 않는다. 고칠 것은 §1-2 결함뿐이고, 고친 내역을 페이지에 명시한다.
2. 배점은 채점도구 hwp 실측값을 쓴다. 합계 100 · 요소별 소계 표기.
3. 평가방법이 학습모듈 PDF 지정과 일치하고, 근거 한 줄이 붙어 있다.
4. 예시 산출물이 실제 문장·실제 그림으로 채워져 있다. 합성·가짜 캡처 금지.
5. 매뉴얼 요구 6항목(출제근거·난이도·루브릭·성취수준환산·검증자·자료보관)이 있다.
6. 유형에 맞는 위젯을 쓴다. A형에 빈칸 채우기를 넣지 않는다.
7. 문서형 미니멀. 그라디언트·원형배지·이모지·다크 코드테마 금지.
8. 강사가 이 페이지만 보고 hwp를 채울 수 있다.

## 5. 진행 순서

```
1차  01 화면설계        A형 엔진 확립      ← 현재
2차  16 DBMS구축        C형 (기존 파일 형식만 맞춤)
3차  15 배포            B형 엔진 확립
4차  05 데이터베이스구현  D형 엔진 확립
5차  나머지 13개         엔진 재사용, 내용만 이관
```

모듈당 반복 절차

```
1. 평가도구 hwp 추출 → 작업지시서·채점표
2. 채점도구 hwp 추출 → 준거별 배점
3. report.pdf       → 수행준거 원문
4. LM PDF           → 평가방법 지정·평가자 체크리스트·활용 서식
5. 유형 판정 (A/B/C/D) → 해당 엔진 선택
6. 내용 이관 + 결함 수정 + 매뉴얼 6항목 보강
7. 예시 산출물 실제 제작
8. items.js / locks.js / modules/mNN.html 연결 → 검증
```

hwp 추출기(`tools/hwptxt.py`)를 만들어 두었으므로 1~4는 모듈당 수 초면 끝난다.
